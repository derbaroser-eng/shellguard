Run untrusted text as arguments,
never as shell syntax.

shellguard is a zero-dependency Python library that kills shell injection at the call site. Every attack token stays data.

pip install shellguard

The bug it kills

full = f"cd {cd} && {oc} run --model {model} {prompt}"

# prompt = "cost (17*23)"
bash: -c: line 1: syntax error near unexpected token `('

# prompt = "`echo INJECTED`"
attacker command executes

The fix

import shellguard as sg

sg.run(["echo", "(17*23)"])          # → '(17*23)\n'
sg.run(["echo", "`echo INJECTED`"])  # → literal text, nothing runs
sg.run(["echo", "$(rm -rf /)"])      # → literal text

Verified against 26 real attacks

(  )  '  "

quote characters and grouping parens never reach a parser

`  $( )

command substitution becomes plain data

;  |  &&

chaining, piping and backgrounding are inert

*  ~  $VAR

globbing, tilde and variable expansion do not fire

>  <

redirection cannot write files

newline

an embedded newline cannot start a second command

Tests: 26/26 passing. Every case runs a real subprocess and asserts on the real exit code and stdout.

Install & use

pip install shellguard

# safe by default
r = sg.run(["echo", user_text])
print(r.stdout, r.returncode, r.ok)

# the dangerous path is refused, not the default
sg.run("echo hi; rm -rf /")   # raises SafetyError
sg.run([...], shell=True)          # raises SafetyError

Why this exists

A production automation system lost hours to exactly this bug: a prompt containing a parenthesis made bash abort, and backticks executed. The failure looked like an unavailable service while short probes still worked. shellguard removes the entire class.

  • Zero dependencies, Python 3.8+
  • MIT licensed, free forever
  • Explicit, opt-in-only shell mode
  • Real exit codes, separate stdout/stderr, timeouts, cwd and env control
