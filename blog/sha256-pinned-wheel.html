The PyPI name was taken, so I shipped a sha256-pinned wheel

Elena Brandt - field note

The name I wanted was already on PyPI. Not a squatter - someone simply got there first. Renaming it to something with -real would have made people trust the library less, so I shipped the wheel from a GitHub Release instead.

The install line

pip install https://github.com/derbaroser-eng/shellguard-lib/releases/download/v1.5.1/shellguard-1.5.1-py3-none-any.whl

Pin the bytes, not just the URL

sha256:88224e4f5df6b54c1b36d221abe7aab739ba037b47076cafaf7f2dc885328ac1

A URL tells you where a file came from. A digest tells you it is still the file you reviewed. For a shell-injection library, that difference matters.

The mistake I made first

My first README linked the release tag page, not the asset. pip does not follow a tag page to find a wheel. If your install line ends in /tag/v1.5.1, it is wrong.

What you give up

No pip install shellguard, no upgrade notices, and a Release can be deleted. In exchange: a deterministic artifact, zero dependencies, Python 3.8+, 142 tests, no namespace politics.
